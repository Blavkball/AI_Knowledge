# Ecosystem Architecture

## Purpose

This document defines the high-level architecture of the KingC Software ecosystem.

It explains how repositories, AI systems, documentation and development workflows connect together to create one unified engineering environment.

# Core Architecture Principle

Each system has one responsibility.

## AI_Knowledge

The source of truth.

Responsible for:

- Architecture
- Standards
- Documentation
- AI employee definitions
- Development processes
- Repository knowledge

AI_Knowledge does not build applications.

It defines how applications are built.

---

## AI_Workstation

The engineering environment.

Responsible for:

- Development coordination
- AI-assisted workflows
- Session continuity
- Engineering guidance
- Documentation management

AI_Workstation helps developers and AI employees operate effectively.

---

## OmniForces

The AI engineering platform.

Responsible for:

- AI services
- Agent workflows
- Memory systems
- Automation
- Future AI employee coordination

OmniForces provides the intelligence layer for the ecosystem.

---

## BlackBall

The commercial software platform.

Responsible for:

- Pool league management
- Fixtures
- Results
- Players
- Statistics
- Competition management

BlackBall represents the customer-facing application layer.

# Repository Independence

Each repository maintains:

- Its own Git history.
- Its own codebase.
- Its own development lifecycle.

However, every repository follows the standards defined by AI_Knowledge.

# Future Expansion

Future repositories should integrate by:

- Having a clearly defined purpose.
- Following AI_Knowledge standards.
- Maintaining independent responsibility.
- Documenting their relationship with the ecosystem.

New systems should strengthen the ecosystem, not create unnecessary complexity.

---

# Architecture Rules

The ecosystem follows these rules:

- One source of truth.
- Clear repository responsibilities.
- Document before expanding.
- Simple over complex.
- Quality over speed.
- Protect working systems.
- Maintain clean Git history.

---

# Obsidian Integration

Obsidian will become a future knowledge navigation layer.

Integration should happen when:

- Architecture documentation is mature.
- Standards are stable.
- Repository relationships are documented.
- AI employee structures are complete.
- Knowledge content is substantial.

Until then, AI_Knowledge remains the primary documentation system.
