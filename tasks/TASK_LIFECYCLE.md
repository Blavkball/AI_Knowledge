# Task Lifecycle

## Purpose

This document defines the standard lifecycle used to create, manage and complete tasks within the KingC Software ecosystem.

The purpose is to ensure every task is understood, completed correctly and recorded properly.

---

# Task Philosophy

KingC Software follows:

> Small clear tasks create reliable software.

Every task should have:

- A clear objective.
- A defined outcome.
- An owner.
- A verification method.

# Phase 1 — Created

## Objective

Define what needs to be completed.

A task should include:

- Task name.
- Purpose.
- Expected outcome.
- Responsible person or AI employee.

---

# Phase 2 — Understood

## Objective

Confirm the requirement is clear.

Before work begins:

- Read relevant documentation.
- Understand the problem.
- Identify affected systems.
- Confirm expected results.

---

# Phase 3 — Planned

## Objective

Create the approach before implementation.

Planning should identify:

- Required changes.
- Files affected.
- Dependencies.
- Testing requirements.

---

# Phase 4 — Built

## Objective

Complete the required work.

Development rules:

- Keep solutions simple.
- Follow existing standards.
- Avoid unnecessary changes.
- Protect working systems.

---

# Phase 5 — Tested

## Objective

Confirm the task works correctly.

Testing may include:

- Feature testing.
- Error checking.
- Integration testing.
- Review.

A task is not complete until it has been verified.

---

# Phase 6 — Documented

## Objective

Preserve knowledge.

Documentation should explain:

- What changed.
- Why it changed.
- Important decisions.
- Future considerations.

---

# Phase 7 — Committed

## Objective

Create a permanent record.

Git requirements:

- Save changes.
- Stage changes.
- Commit with a meaningful message.
- Push when required.

---

# Phase 8 — Verified

Before completion confirm:

## Saved?

YES

## Git?

YES

## Graphify?

YES (where required)

## Documentation?

YES

---

# Task Completion

A task is complete only when:

- The work is finished.
- Testing is complete.
- Documentation is updated.
- Git is clean.
- Verification is complete.

---

# AI Employee Usage

All AI employees follow this lifecycle.

Tasks should be:

- Assigned clearly.
- Completed systematically.
- Verified before closing.

---

# Continuous Improvement

The task lifecycle should improve as KingC Software grows.

Changes must be documented in AI_Knowledge before adoption.
