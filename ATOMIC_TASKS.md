# Purpose

This document defines the documentation standard used throughout the KingC Software ecosystem.

Every document created by human engineers or AI Employees shall follow this standard.

---

# Standard Document Header

Every document shall begin with the following metadata.

```
# Document Title

**Document:** DOCUMENT_NAME.md

**Version:** X.Y

**Status:** Draft | Operational | Complete | Archived

**Owner:** KingC Software

**Last Updated:** DD Month YYYY

**Source of Truth:** Repository Name

**Applies To:**

- Repository Name

---
```

---

# Source of Truth

Each document has one authoritative location.

No document should have multiple editable copies.

Other repositories should reference the original rather than duplicate it.

---

# Versioning

Major versions represent structural or architectural changes.

Minor versions represent content improvements or corrections.

Examples:

- 1.0
- 1.1
- 2.0

---

# Status Values

| Status | Meaning |
|---------|---------|
| Draft | Under development |
| Operational | Current engineering standard |
| Complete | Finished and stable |
| Archived | Retained for history only |

---

# Naming Convention

Document names should use uppercase letters with underscores.

Examples:

- SYSTEM_OVERVIEW.md
- AI_EMPLOYEES.md
- ARCHITECTURE.md
- KCES.md

---

# Engineering Principles

Documentation should be:

- Accurate
- Version controlled
- Single source of truth
- Human readable
- AI readable
- Repository independent where possible

---

# Relationship to Graphify

Graphify provides semantic understanding.

Git provides history.

Documentation provides organisational knowledge.

Together they form the knowledge foundation of the KingC Software ecosystem.
